我们把社群多年沉淀的**行业研报、会议纪要、社群资料**，做成了一个能被 AI 助手直接调用的「知识连接器」——**刺桐说金融知识**。装上它，你的 AI 助手就相当于多了一位熟悉刺桐说全部资料的"资料员"：找资料、读原文、做对比，一句话就能使唤。

不论你是 WorkBuddy 用户，还是习惯用 Claude Desktop、Cursor、Trae 等 MCP 客户端，都可以用上它。本文一次说清：它是什么、能做什么、怎么装，以及加入会员能同时得到什么。

## 一、为什么要做「刺桐说金融知识」连接器

### 资料一直都在，只是"调不动"

刺桐说社群的投研资源品类很全：行业深度研报、嘉宾分享纪要、成员交易复盘、读书活动资料……但过去它们更像一座"仓库"：

- 想找某个行业的资料，得先翻聊天记录、再翻文件夹，靠记忆和耐心；
- 找到之后还要自己复制、粘贴到 AI 里，才能请它帮忙分析；
- 换个工具、换台电脑，一切又要重来。

### 让 AI 直接"走进"资料库

连接器解决的，就是把"人找资料 → 喂给 AI"这一步彻底省掉。安装之后，你的 AI 助手可以**主动检索、浏览、调取**刺桐说金融知识里的内容，再用它擅长的方式帮你归纳、对比与追问。

### 三个让我们觉得"必须做"的理由

1. **省时间**：从"翻半天"到"问一句"。
2. **不挑工具**：WorkBuddy 里一键安装；其他 MCP 客户端填一行配置即可接入。
3. **只读、安全**：全部工具都是只读查询，会员凭证仅用于验证身份，不涉及任何上传、修改或删除。

## 二、它到底能做什么：4 个只读工具

连接器为你的 AI 助手准备了 4 个工具，覆盖"找库 → 找条目 → 读原文"的完整链路：

| 工具 | 它能做什么 | 你可以这样问 |
| --- | --- | --- |
| `citongshuo_knowledge_list` | 列出 / 搜索刺桐说金融知识里有哪些知识库 | "看看知识库里都有什么？" |
| `citongshuo_knowledge_browse` | 浏览知识库目录，逐层看到文件夹与文件 | "行业研报里都有哪些分类？" |
| `citongshuo_knowledge_search` | 在知识库内按关键词搜索，返回条目与高亮片段 | "搜一下新能源汽车的资料" |
| `citongshuo_knowledge_read` | 调取条目原文（文件 / 网页类返回访问链接） | "玻璃基板那篇研报原文在哪看？" |

### 一条调用链，AI 自己会跑完

你只需要用大白话提问，剩下的"定位知识库 → 锁定条目 → 取回原文"由 AI 自动串联：

```mermaid

    A["你的一句话提问"] --> B["citongshuo_knowledge_list<br/>定位知识库"]

    C --> D["citongshuo_knowledge_read<br/>取回原文或访问链接"]
```

工具返回的是纯文本结构化内容，AI 会先归纳再呈现给你。下面是两个简化示例（内部编号已隐去）：

### 全部只读，用起来没有负担

四个工具都是**只读查询**：不会上传文件、不会修改或删除任何内容，也不需要为每一次调用做二次确认。你可以放心把它当作一个"只进不出"的资料入口。

## 三、真实使用示例：它到底好用在哪

下面这些场景，都是装上连接器之后，你可以直接对 AI 说的话。

### 场景一：一句话摸清资料家底

> **你**：刺桐说金融知识里都有哪些内容？
>
> **AI**：（调用 `citongshuo_knowledge_list`）目前可访问《刺桐说金融知识库》，涵盖行业研报、会议纪要、社群资料等分类……

过去要先知道"有什么"，才能开始找；现在只需要问一句，家底一目了然。

### 场景二：给某个行业做"资料速览"

> **你**：帮我把知识库里新能源汽车相关的研报找出来，整理成一份要点清单。
>
> **AI**：（先定位知识库 → 搜索"新能源汽车" → 命中若干条 → 逐条调取原文 → 输出结构化要点清单）

这正是连接器最有价值的地方：**把"检索"和"阅读"合并成一次对话**，AI 从标题一路读到原文，最后交给你的是结论，而不是一堆待读的链接。

### 场景三：把原文链接"要"出来

> **你**：玻璃基板那篇研报原文在哪里看？
>
> **AI**：（调用 `citongshuo_knowledge_read`）《……玻璃基板……》原文访问链接：https://…

对于 PDF、Word 等文件类资料，连接器会返回可访问的原文链接，点开即是原汁原味的研究报告，方便你精读、批注与存档。

### 场景四：跨资料对比，做"交叉验证"

> **你**：对比一下知识库里关于"AI 算力"和"新能源"的资料，说说各自的核心逻辑是什么？
>
> **AI**：（分别检索两类条目 → 读取原文 → 并排对比行业驱动、关键变量与风险点）

社群最大的价值，是不同视角的**交叉验证**。以前这需要在群里等好几位嘉宾陆续发言；现在，你可以让 AI 先把资料里的多空逻辑摆在一起，再由你来做判断。

## 五、非 WorkBuddy 用户：用任意 MCP 客户端接入

刺桐说金融知识是一个标准的 **MCP（Model Context Protocol）Streamable HTTP 服务**。只要你的 AI 客户端支持 MCP，就可以接入，不限于 WorkBuddy。

### 连接信息

- **服务地址**：`https://knowledge.citongshuo.online/mcp`
- **认证方式**：`Bearer <你的会员密钥>`
- **协议**：MCP Streamable HTTP

### Claude Desktop / Cursor / Trae 配置示例

在客户端的 MCP 配置中加入下面这段即可：

```json
{
  "mcpServers": {
    "citongshuo-knowledge": {
      "url": "https://knowledge.citongshuo.online/mcp",
      "headers": { "Authorization": "Bearer <你的会员密钥>" }
    }
  }
}
```

保存并重启客户端，你的 AI 助手就会多出 4 个 `citongshuo_knowledge_*` 工具，用法与 WorkBuddy 中完全一致。

### 连通性自检（可选）

配置完成后，可用一条命令确认服务是否打通（将 `<你的会员密钥>` 替换为实际密钥）：

```bash
curl -X POST https://knowledge.citongshuo.online/mcp \
  -H "Authorization: Bearer <你的会员密钥>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

返回 4 个 `citongshuo_knowledge_*` 工具名，即表示连接正常。

> 不同客户端的配置文件位置不同，请以各自官方说明为准；请勿把会员密钥分享给他人，也不要把含密钥的配置提交到公开仓库。

刺桐说金融知识内的资料为社群内部投研资源，仅限会员本人查阅使用。请尊重原创与版权，不要外传、转发或用于商业用途。

### 关于原文与检索范围

- 文件类（PDF、Word、Excel、PPT 等）返回的是**访问链接**，请通过链接打开原文；
- 笔记类条目不提供正文，连接器会给出提示并引导你在客户端中查看；
- 站内搜索为**标题级检索**，用于快速定位条目；深入分析请配合"读取原文"完成。
